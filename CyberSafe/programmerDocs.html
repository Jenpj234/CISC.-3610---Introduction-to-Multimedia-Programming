Programmer Guide

How CyberSafe is structured and how to modify or extend the JSON dataset to create a custom learning set.

Overview

CyberSafe is built with plain HTML5, CSS3, and vanilla JavaScript — no frameworks or build tools required. All topic content is stored in a single data.json file, which the app fetches at runtime and uses to dynamically build the dropdown menu and topic cards.

This makes it straightforward to swap in an entirely different dataset without touching any HTML or JavaScript.

File Structure

CyberSafe/
  ├── cyberSafe.html — main app page
  ├── cyberSafe.css — all styles
  ├── cyberSafe.js — app logic + service worker registration
  ├── data.json — all topic content ← edit this
  ├── manifest.json — PWA install config
  ├── serviceWorker.js — offline caching
  ├── promo.html — promotional landing page
  ├── promo.css — styling of promotional landing page
  ├── programmerDocs.html — programmer documentation
  ├── programmerDocs.css — styling of programmer documentation
  ├── images/ — topic images + app icons + screenshots
  └── audio/ — topic narration mp3 files

JSON Format

The data.json file contains a single topics array. Each object in the array represents one topic card in the app. 

{
  "topics": [
    {
      "title":       "Phishing",
      "icon":        "🎣",
      "description": "What the threat is and how it works.",
      "prevention":  "Steps to protect yourself.",
      "image":       "images/phishing.jpg",
      "audio":       "audio/phishing.mp3"
    }
  ]
}

Field Reference

Field Type Required Description
title string ✅ Yes The name of the topic, shown in the dropdown and card header.
icon string ✅ Yes An emoji shown next to the title in the dropdown and card.
description string ✅ Yes A paragraph explaining what the threat is.
prevention string ✅ Yes A paragraph with prevention tips, shown in the green info box.
image string ⬜ Optional Relative path to an image file. Card hides the image if omitted.
audio string ⬜ Optional Relative path to an MP3 file. Audio player hides if omitted.

Adding a New Topic

To add a topic, open data.json and add a new object inside the topics array. Copy the template below and fill in your content: 

{
  "title":       "Your Topic Title",
  "icon":        "🔐",
  "description": "Explain what this topic is about.",
  "prevention":  "Explain how to stay safe.",
  "image":       "images/your-image.jpg",
  "audio":       "audio/your-audio.mp3"
}
1

Add the object to data.json

Paste the template inside the topics array, after the last closing } and before the closing ]. Separate it from the previous entry with a comma.

2

Add your image

Save your image to the images/ folder and make sure the filename matches what you wrote in the image field.

3

Add your audio

Save your MP3 to the audio/ folder. You can record your own voice or use a text-to-speech tool like ElevenLabs or TTSMaker.

4

Reload the app

Refresh the browser. Your new topic will appear automatically in the dropdown — no HTML changes needed.

💡 Make sure your JSON is valid — a missing comma or unclosed bracket will break the fetch. Use jsonlint.com to validate before saving.

Swapping the Dataset

Because the app reads entirely from data.json, you can swap it out for a completely different subject without changing any JavaScript or HTML.

For example, to turn CyberSafe into a Marine Life educational app: 

{
  "topics": [
    {
      "title":       "Blue Whale",
      "icon":        "🐋",
      "description": "The blue whale is the largest animal on Earth...",
      "prevention":  "Conservation tip: reduce ocean plastic...",
      "image":       "images/blue-whale.jpg",
      "audio":       "audio/blue-whale.mp3"
    }
  ]
}

The only field names that must stay the same are title, icon, description, prevention, image, and audio — since cyberSafe.js reads those specific keys.

💡 If you rename the top-level key from "topics" to something else, you'll also need to update the matching reference in cyberSafe.js — look for data.topics on line 2.

Service Worker & Caching

The service-worker.js file caches core assets on install so the app works offline. If you add new files (images, audio, pages), add their paths to the ASSETS array to make them available offline: 

// service-worker.js
const ASSETS = [
  '/',
  '/index.html',
  '/cyberSafe.css',
  '/cyberSafe.js',
  '/data.json',
  '/images/your-new-image.jpg',  // ← add new files here
  '/audio/your-new-audio.mp3'
];

After updating the service worker, bump the cache name (e.g. cybersafe-v2) so browsers pick up the new version instead of serving the old cached files.
